De formulario en formulario a un solo comando.

Grade Uploader lee las notas exportadas de Moodle y las sube al sistema oficial de Notas Parciales sin capturarlas una por una. Este recorrido simula, paso a paso, cómo se usa — con puntos, insignias y un certificado al final.

📥 Moodle .xlsx→ 📋 plan→ 🧐 revisar plan.csv→ 🧪 apply --dry-run→ 🚀 apply --commit→ 🏛️ Notas Parciales
🔒 Es una simulación educativa. No hace falta escribir contraseñas ni cookies reales en ningún campo de esta página — todas las "salidas" que verás son datos de ejemplo, iguales a los del script real.

Cómo funciona la autenticación

Un archivo, dos líneas

El script se conecta al sistema de Notas Parciales con tu usuario y contraseña del SSO UNED. Hace el handshake NTLM contra el servidor y mantiene la sesión activa mientras corre — no hay ningún otro paso de tu parte.

🔑

Usuario y contraseña SSO

El mismo que usás para el correo institucional. Sin @uned.ac.cr, solo el usuario. Se configura una sola vez, en tu archivo .env.

✨

Sesión con el servidor

El script la maneja solo, en memoria, mientras corre. No hay que tocar el navegador para nada.

Lo que resuelve el script por vos
Guarda el contexto del curso (--escuela --catedra --encargado --tutor --modelo) tras el primer probe exitoso — no hace falta volver a escribirlo
Detecta el grupo de cada centro universitario solo, comparando cédulas del xlsx contra el servidor
Si algún parámetro no corresponde a un curso real, te lo dice explícitamente — nunca te deja adivinando por qué no pasó nada
PASO 03○
Configuración — dos líneas y listo

Completar el .env

Abrí el archivo .env que creó instalar.bat, con el Bloc de notas, y completá tu usuario y contraseña del SSO UNED (los mismos del correo institucional, sin @uned.ac.cr). Practicá acá:

.env
NP_NTLM_USER=<pendiente> NP_NTLM_PASSWORD=<pendiente>

🔒 Nada de esto se envía a ningún lado — es una simulación. El archivo real nunca se sube a Git (está en .gitignore), y esto es todo lo que hay que configurar: dos líneas, una sola vez.

PASO 04○
Siempre primero — y solo una vez por curso

Modo probe — verificar y guardar el contexto

Confirma que las credenciales funcionan y muestra los instrumentos de evaluación del grupo. No escribe nada. Si todo sale bien, guarda esos códigos para que no haya que volver a escribirlos.

python notasparciales_upload.py probe --ano 2026 --pac 3 --escuela 03 --catedra 253 --encargado ARODRIGUEZP --tutor 0401230456 --asignatura 00883 --cu 42 --grupo 1 --modelo 4

🧩 Pregunta 1 — En la fila de Ana, la nota es un guion ( — ). ¿Qué hace el script con eso?
✅ Correcto — el guion se traduce al código 998 ("no presentó") en Notas Parciales.
❌ No — un guion nunca se convierte en 0 ni se ignora: es el código 998, "no presentó".
🧩 Pregunta 2 — Moodle califica de 0 a 100. Notas Parciales usa 0 a 10. ¿Qué hace el modo plan?
✅ Correcto — la conversión 0–100 → 0–10 es automática en el modo plan (no en el modo csv, ojo).
❌ No — el modo plan convierte solo, dividiendo entre 10.
PASO 06○
El paso auditable

Modo plan — generar el plan antes de subir nada

Lee el xlsx, compara contra lo que ya existe en el servidor, y escribe un plan.csv revisable en Excel. Los centros universitarios (CU) salen solos de la columna "Institución" del xlsx, y el número de grupo de cada uno se detecta comparando cédulas contra el servidor — no hace falta escribirlos a mano.

python notasparciales_upload.py plan --ano 2026 --pac 3 --asignatura 00883 --xlsx calificaciones_moodle.xlsx
PASO 07○
La red de seguridad

Antes de aplicar de verdad

🧩 ¿Qué pasa si corrés apply --dry-run?
✅ Correcto — --dry-run es el ensayo. Solo --commit escribe en Notas Parciales.
❌ No — nada se escribe hasta que uses --commit. --dry-run es puro ensayo.
PASO 08○
El final

Modo apply — ensayo y luego commit

python notasparciales_upload.py apply --plan notas_plan.csv --dry-run
python notasparciales_upload.py apply --plan notas_plan.csv --commit
PASO 09○
La red de seguridad, siempre a mano

Modo estado — ¿en qué iba?

Cerraste la terminal, volviste al otro día, o simplemente no te acordás qué seguía. estado lee solo archivos de tu computadora — no toca el servidor, no lleva parámetros — y te dice exactamente qué falta y cuál es el próximo comando.

python notasparciales_upload.py estado

Referencia rápida

Cuando algo falla

probe o plan dicen "0 estudiantes" pero la autenticación fue exitosa

El servidor devuelve tablas vacías (sin error) cuando algún código no corresponde a un grupo real: --asignatura, --modelo, --cu, --grupo o --pac. El script te lo dice explícitamente — no es un problema de usuario/contraseña.

¿Tengo que indicar el grupo de cada centro universitario a mano?

No. El modo plan los detecta solo comparando las cédulas del xlsx contra el servidor. --cu-grupo CU=GRUPO sigue existiendo por si necesitás forzar un valor manualmente.

¿El modo csv también convierte la escala 0–100 a 0–10?

No. El modo csv espera las notas ya en escala 0–10. Solo el modo plan hace la conversión automática desde un xlsx de Moodle.

Perdí el hilo. ¿Por dónde empiezo de nuevo?

Con estado. Es justamente para eso — no necesita parámetros y siempre te da el próximo comando exacto.
